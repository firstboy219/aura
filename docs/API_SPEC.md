# API_SPEC.md — Phase 1 REST API and CLI

Machine-readable contract: `contracts/api/openapi.yaml` (Phase 1 endpoints only, Blueprint §11).
Evidence level: **design-reviewed**.

## Transport and auth
- Base `http://127.0.0.1:7400/api/v1` (container listens on 7400, published on host loopback only, ADR-0014).
- `Authorization: Bearer <token>`; token = 256-bit random, generated by `aura serve` on first start into
  `/var/lib/aura/api_token` (0400) if `server.token_file` is absent; CLI reads the same file. Constant-time compare.
- `GET /system/health` is unauthenticated and returns no internals.
- Every response has `X-Request-Id`; errors are `{"error":{"code","message","request_id"}}`; no stack traces.
- Limits: request body 64 KiB; 20 req/s per token (burst 40); `Idempotency-Key` on `POST /tasks` deduplicates.

## Endpoints
| Method & path | Behaviour |
|---|---|
| `POST /tasks` | Validate objective/tools/domains/budget (budget ≤ config caps), create task + `TASK_CREATED`, enqueue. 201 |
| `GET /tasks` | List with `state`, `limit`, `cursor` |
| `GET /tasks/{id}` | Projection incl. state, reason, wait_reason, lineage, cost |
| `GET /tasks/{id}/events` | Ordered events (`after_seq` for polling); redacted |
| `POST /tasks/{id}/cancel|pause|resume` | Legal transitions only, else 409 `invalid_transition` |
| `GET /approvals` | Pending approvals with tool, side effect, target, full parameters, hash, expiry |
| `POST /approvals/{id}/approve` | Body `{action_hash}` must equal stored hash (409 `approval_mismatch`); expired → 410; single use |
| `POST /approvals/{id}/reject` | Task step fails with `approval_rejected` |
| `GET /system/health` | `{live, ready, version, checks}`; 503 when not ready (DB, migrations, secrets) |
| `GET /system/resources` | Core RSS, worker state/RSS, WAL size, queue depth, budget today |
| `POST /system/stop` | Kill switch (T9); 202 with count |

## CLI (`aura`)
`serve`, `task create "<objective>" [--tool …] [--allow-domain …] [--max-cost …]`, `task list|show|cancel|pause|resume
<id>`, `trace <id> [--follow]`, `approve <approval-id>` (shows full preview and hash, asks y/N), `reject <id>`,
`stop --all` (asks confirmation), `doctor` (config, secrets perms, SQLite version/FTS5/WAL, migrations, disk, worker
spawn test, provider reachability without spending).
