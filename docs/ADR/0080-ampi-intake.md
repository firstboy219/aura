# ADR-0080 — AMPI intake: perception arrives as untrusted evidence, AURA decides
Status: accepted (owner "Silahkan", 2026-11-17, after being asked before touching the running AURA). AMPI is a separate platform (own repo, DB, release). It delivers context packets of perception; AURA remains the only policy, memory and action authority.
- **Route** `POST /api/v1/ampi/events`: dormant (404) until the owner stores the signing key in the vault (`PUT /api/v1/admin/credentials/ampi_signing_key`, the key AMPI shows once when the subscription is created). Reachable only from the private network: a request carrying `CF-Connecting-IP`, `X-Forwarded-For` or `X-Real-IP`, or coming from a public address, gets 404 as if the route did not exist.
- **Authentication**: `X-AMPI-Signature: sha256=HMAC(key, timestamp + "." + body)` with `X-AMPI-Timestamp` within ±5 minutes (AMPI signs every attempt freshly). The owner's API token is not accepted here, and the AMPI key opens nothing else. Failures are audited (`AMPI_AUTH_FAILED`, no content).
- **What it does**: validates the packet (protocol `ampi-perception`, event id, session), stores it **once** per event id (a replay or repeated delivery is acknowledged as `duplicate` so AMPI stops retrying), and audits `AMPI_EVENT_RECEIVED` with ids and sizes, never content. Body limit 256 KiB; retention 14 days, enforced on every intake.
- **What it never does**: start a task, call NEXUS or any tool, or treat the packet as instructions. Text read from media (OCR, transcripts) is marked `untrusted_content` and the owner's view repeats that it is data. Using a packet in a task is a separate, later decision of AURA's own policy.
- **Owner view**: `GET /api/v1/admin/ampi` (summaries) and `?event_id=` (one packet, labelled as data).
- Migration 0027 (additive: `ampi_events`). Tests: dormant until configured, signature/key/tamper/stale/missing-time refusals audited, owner token refused, stored once and replay `duplicate`, no task created by instruction-like text, proxied and public-address requests get 404, malformed and oversize packets refused; a mutation check (signature comparison disabled) makes the tests fail.
